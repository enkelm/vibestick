## Diagnostic evidence

The persisted binding was correct:

```json
"share": {"kind": "overlay"}
```

The reader discovered exactly one target raw-HID device, one Xbox
GameController profile, and one non-nil Share element. Handler installation was
observed. A controlled trace then showed A from both backends:

```text
[raw-hid] a pressed
[normalized] a pressed
[game-controller] a pressed
[raw-hid] a released
[normalized] a released
[game-controller] a released
```

The same trace showed no Share event from GameController. Enabling
`GCController.shouldMonitorBackgroundEvents` allowed ordinary GameController
events in the background but did not make Share appear. Changing
`preferredSystemGestureState` from `.disabled` to `.alwaysReceive` also
produced neither an app event nor a macOS screenshot/recording gesture.

An `IOHIDManagerRegisterInputReportCallback` probe captured this report when
Share changed:

```text
id=32 length=19
20 00 90 2C 00 00 00 00 00 00 A2 02 AB FB 73 FD 75 FA 00
```

The GIP header says message type `0x20` with payload length `0x2C` (44 bytes),
but Apple's `XboxSeriesXGamepad` service provides only 19 bytes total: the
4-byte header and 14-byte standard gamepad payload plus report framing. The
Microsoft GIP specification places Share in an input-report extension beyond
that standard payload. `IOHIDValue` is truncated identically. `hidutil` shows
no second synthetic or consumer HID service that could supply the extension.

## Triage decision

The operator selected direction 2 for the initial milestone:

1. Read the complete USB interrupt report below Apple's truncated HID service.
   This is the most faithful USB implementation but may require exclusive USB
   interface access or a DriverKit component.
2. **Selected:** qualify Bluetooth, where GameController physically emits
   `buttonShare`, and update controller identification and acceptance setup.
3. Infer Share edges from extension-only GIP updates whose visible standard
   state did not materially change. This is smaller but risks false Share
   events from invisible extensions or controller noise and should not be
   selected without a long-running physical false-positive test.

## Bluetooth probe

A GameController-only physical probe succeeded after reconnecting the same
controller over Bluetooth Low Energy:

```text
[controller] vendor=Xbox Wireless Controller category=Xbox One
[controller] Share element available
[a] value=1.0 pressed=true
[a] value=0.0 pressed=false
[share] value=1.0 pressed=true
[share] value=0.0 pressed=false
```

macOS identifies the Bluetooth target as Microsoft `045E:0B13`, transport
`Bluetooth Low Energy`, firmware `5.15.3168.0`. This gives a lower-cost
qualified path: recognize `0B13` as the same target model, use its raw HID
service for exact-device lifecycle/correlation, and give GameController
ownership of all production controls in Bluetooth mode. USB `0B12` can remain
diagnostic or explicitly unsupported for Share until complete USB reports are
available.
